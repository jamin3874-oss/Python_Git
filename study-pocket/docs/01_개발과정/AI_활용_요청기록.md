# 대표 요청과 반영 결과

전체 대화 원문이 아닌, 실제 사용자 요구를 발췌·요약한 과정 기록입니다. 응답 날짜·실행 시간·실제 인식률을 추정하여 넣지 않았습니다.

| 사용자 요청 | 문제 정의 | 반영 결과 |
|---|---|---|
| 전체 코드를 확인하고 앱을 실행·오류 수정 | 로컬에서 시작할 수 있는 상태 필요 | 실행 설정, 검사 기록과 API 연결 흐름 정비 |
| 환경변수로 설정해줘 | 소스에 키가 들어가면 유출 위험 | 서버 환경변수와 브라우저 임시 입력 구분 |
| 원하는 방식으로 요약해달라고 요청하는 칸 | 고정 요약만으로는 공부 방식 반영 어려움 | AI 요청사항 자유 입력 |
| 항만공학이 아닌 시험 공부 사이트 | 과목에 제한된 UX | 과목 공통 명칭·프롬프트·설명 |
| 궁금한 것도 물어보고 AI와 대화 | 일회성 결과물만으로 이해를 돕기 어려움 | 여러 차례 질문·후속 설명·노트 참고 대화 |
| 읽기·저장 속도가 느림 | 미리 렌더링하고 작은 요청을 반복 | 기존 앱 묶음 저장, 새 앱 필요 시 렌더링 |
| 실제 강의자료 배포 #1·#2로 검증 | 합성 예시만으로 실제 PDF 특성 확인 어려움 | 47쪽·49쪽 자료를 사용한 기존 검증과 렌더링 기록 |
| 작은 손글씨도 인식하고 DPI 설명 | 전체 해상도와 비용의 균형 | 영역 확대·판독 수정·불확실성 안내 |
| 잘못 올린 PDF 삭제 | 자료 수정 및 개인정보 정리 필요 | PDF 단위·프로젝트 단위 삭제 |
| X는 개인적인 범위 제외 필기 | OX 답 판정과 요구 불일치 | 자연어 요청과 문맥 기반 제외 |
| PDF 전체를 한 번에 처리 | 슬라이드 단위 수작업 과다 | 전체 자동 읽기·계층 통합·이어가기 |
| 결과 폴더에 과정 저장, 타인 배포·휴대폰 앱 | 과제 제출과 실제 사용성 확장 | 제출 폴더, 순수 JS/Python 프로젝트, PWA·배포 설정 |

## 서비스 안에서 사용할 요청 예시

```
직접 X 표시한 부분은 시험 범위에서 제외해줘.
여러 PDF에서 같은 개념을 묶고, 처음 배우는 사람도 이해하게 설명해줘.
수식은 기호의 의미와 단위를 같이 적고, 판독이 애매한 숫자는 확인 필요라고 표시해줘.
마지막에는 서술형 예상 문제 5개와 풀이의 핵심을 넣어줘.
```

```
암기 위주가 아니라 원인과 결과가 연결되게 정리해줘.
서로 비슷한 개념은 차이점을 비교하고, 원본 PDF의 파일 번호와 쪽수를 알려줘.
```

후속 대화 예: “방금 노트의 두 개념이 왜 다른지 실생활 예시로 설명해줘.”

## 이번 코드 작업에서 AI를 활용한 방식

요구를 화면·데이터·API로 분해하고, 기존 앱과 새 과제 앱의 차이를 정리했습니다. 코드 작성 후 키 누출·리디렉션·큰 입력·모의 API 오류·전체 읽기·이어가기 등을 테스트했습니다. 모의 테스트 결과를 실제 모델의 정답률이나 휴대폰 설치 성공으로 바꾸어 주장하지 않았습니다.
