# 테스트 결과

검사일: 2026-11-04. 대상은 이번에 만든 `app/`입니다.

## 자동 검사

| 검사 | 결과 | 범위 |
|---|---|---|
| JavaScript | 27/27 통과 | 원본 계획·전체 자동 처리·체크포인트·모의 API·입력 보호·PWA 선언 |
| Python | 14/14 통과 | 고정 API 주소·키 선택·메시지·JPEG 검증·오류·리디렉션·타임아웃 규약 |
| 로컬 HTTP | 통과 | 주요 7개 리소스, 소스 파일 비노출, 키 없음 401, 외부 Origin 403, API 캐시 제외 |
| 빌드·문법 | 통과 | 순수 프론트 배포 파일·아이콘·서비스 워커·Sites Worker 생성 |
| 실제 PDF 렌더링 | 통과 | 47쪽·49쪽 문서 열기, 대표 6쪽·확대 2곳 |

전체 노트 처리 테스트는 실제 `public/workflow.js`를 모의 PDF 렌더러·모의 모델·저장 대역으로 실행합니다. 501쪽·두 파일을 끝까지 처리하고 단일 결과로 끝나는지, 작은 PDF는 불필요한 합성 없이 한 호출로 끝나는지 검사합니다. 이미지 합계 크기에 따라 페이지 수보다 일찍 묶음을 나누는 경우, 실패·중단 뒤 완료한 읽기를 건너뛰는 경우, 통합 단계 도중 재개하는 경우도 포함합니다.

공개 방문자가 서버 환경변수의 키를 무단으로 사용할 수 없고, 개인 키가 우선 사용되는지 검사했습니다. 외부 Origin·임의 이미지 URL·시스템 역할·큰 요청·API 리디렉션을 차단하며 상위 API 오류 본문과 키가 사용자 응답으로 나오지 않는지 확인했습니다. AI HTML 출력은 실행되지 않도록 이스케이프합니다.

## 실제 자료 확인

이전에 사용자가 지정한 두 강의자료를 읽기 전용으로 사용했습니다. 각각 PDF.js에서 47쪽·49쪽으로 확인했습니다. 표지 역할의 첫 쪽, 중간 쪽, 마지막 쪽을 선택해 각 세 쪽을 생성했습니다. 전체 이미지는 약 1318×1864~1865px, 확대는 1275×902px였습니다. 출력 중 첫 자료 첫 쪽, 둘째 자료 25쪽, 첫 자료 필기 확대 이미지를 직접 살펴 한글·사진·도표·필기 스트로크가 표시되는 것을 확인했습니다. 원본 파일은 수정하지 않았습니다.

처음 Node 렌더링 검사에서는 기본 Worker 파일 경로와 최신 표준 메서드 호환성 문제가 드러났습니다. 테스트의 명시적 Worker 경로를 수정하고, 앱이 배포하는 PDF.js를 같은 버전의 **5.7.284 legacy 호환 빌드**로 맞춘 뒤 다시 통과했습니다. Node의 선택적 native-canvas 탐색 및 일부 TrueType 함수에 관한 경고는 있었지만, 주입한 native-canvas 어댑터로 결과 이미지 생성은 완료했습니다.

개별 렌더링 수치는 `실제PDF_렌더링결과.json`에 있습니다. 이는 로컬 Node/PDF.js/native canvas 측정이며 브라우저 전체 저장 속도 또는 휴대폰 성능 측정이 아닙니다. 실제 PDF·이미지는 소스·배포·제출 ZIP에서 제외합니다.

## 이번에 확인하지 않은 것

- 실제 유료 Codyssey 호출과 계정의 모델 사용 가능 여부
- 작은 손글씨·수식·개인 X 표시의 실제 AI 정답률
- 브라우저 화면의 클릭·파일 선택·IndexedDB 저장을 포함한 종단간 UI 실행
- Android/iPhone 실기기의 설치 완료, 터치 드래그, 절전 후 복구, 대용량 PDF 메모리
- Vercel 프로젝트 계정 연결 후 Python 함수의 실제 배포 실행

브라우저 자동 제어는 Windows에서 현재 URL을 확실하게 확인할 수 없다는 이유로 도구가 중단했습니다. 이를 우회하지 않았으며 실제 화면 스크린샷을 임의로 만들지 않았습니다.
