# 매번 API 키를 입력하지 않는 서버 AI 연결

- 배포: https://study-pocket-six.vercel.app/
- 서버: Vercel `jaemin13/study-pocket`, 프로덕션 `main`
- 서버 환경변수: `CODYSSEY_API_KEY`, `STUDY_APP_ACCESS_TOKEN` 두 값을 암호화 등록
- 화면: **AI 연결 → 앱 접속 코드 → 서버 AI에 연결**
- 유지: 동일 브라우저에서 30일. 다른 기기·쿠키 삭제·만료 후 다시 연결
- 해제: **AI 연결 → 이 기기 연결 해제**

API 키를 프론트엔드에 넣지 않습니다. 접속 코드는 로그인 요청에서 한 번 사용하고 입력란을 비웁니다. 이후 `Secure; HttpOnly; SameSite=Strict; Path=/` 로그인 쿠키만 사용합니다. 쿠키는 서명을 검증하며 API 키·접속 코드 변경 시 이전 쿠키도 무효가 됩니다. 별도의 개인 API 키 입력 기능은 유지하고 그 키는 탭 메모리에서만 사용합니다.

접속 코드를 아는 사람의 요청은 서버 키의 사용량에 포함됩니다. 코드를 허용할 사람에게만 전달하고 GitHub·제출 ZIP에는 포함하지 않습니다. 서버 키와 접속 코드는 없거나 로그인하지 않은 경우 익명 AI 요청을 거절합니다. PDF 원본 저장에는 API 연결이 필요하지 않습니다.

PDF 업로드 버튼은 API와 분리했습니다. 파일 형식 확인과 기기 저장 진행·실패를 표시하고, 저장소 무응답은 시간 제한 후 오류로 알립니다. 기존 자료를 삭제하는 복구는 수행하지 않습니다. 앱 초기화 오류도 화면에 표시하며, 새 서비스 워커가 준비되면 업데이트 버튼을 제공합니다.

검증: JavaScript 32개, Python 21개 통과. DOM·IndexedDB 모의 실행에서 두 PDF 저장, 원본 바이트 유지, 노트 화면 전환, 미인증 AI 연결 안내, 잘못된 PDF 거절을 확인했습니다. 실제 브라우저 자동 점검은 Windows 도구의 URL 확인 차단으로 완료하지 못했습니다. 브라우저 파일 선택기와 휴대폰의 실제 업로드 완료를 검증했다고 주장하지 않습니다.
